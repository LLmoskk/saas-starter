# GitHub Issues

操作需求、规格与实施任务时使用 GitHub Issues，优先通过 gh CLI。首次写入前核对当前仓库 remote 与目标仓库，避免提交到模板源或 fork 的上游。

- Issue 写明问题、目标、范围与验收条件，引用相关领域决策；具体实现只写已确认的约束。
- 多行正文写入临时文件，通过 `--body-file` 传入，保留换行并避免 shell 展开正文。
- 拆分任务时记录父子关系和阻塞项；使用当前 CLI 与仓库实际支持的能力，必要时用任务清单和链接表达。
- 关闭时说明完成结果、实际验证与未完成事项。只在用户要求或明确工作流授权时创建、评论或修改外部记录。
- 分诊角色见 `triage-labels.md`；领域术语与架构决策见 `domain.md`。
