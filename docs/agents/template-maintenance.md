# 模板初始化与规则回流

新项目初始化、从业务项目提炼经验或升级模板规则时读取。以模板 main 分支为基线；功能分支的业务实现不自动成为通用能力。

## 新项目初始化

1. 从模板 main 创建项目，保留 `AGENTS.md`、`CODING_STANDARDS.md`、`DESIGN.md`、`.agents/skills`、检查脚本、`.githooks` 和 CI 工作流；记录模板提交号，便于后续比较。
2. 先检查实际目录、依赖、脚本与配置，再调整品牌、域名、主题、语言、商品和业务权益。配置与 SEO 按 `docs/configuration.md`，支付按 `docs/waffo.md`，发布按 `docs/cloudflare.md`。模板的支付记录能力不等于业务权益已经实现。
3. 修改设计稿时同步 `DESIGN.md` 与主题；保留 Tailwind 和共享控件实现路径，原子组件按 `DESIGN.md` 优先使用 shadcn；以实际初始化状态区分新增与存量迁移。外部设计系统的视觉目标不要求复制它的组件库或样式组织方式。
4. 领域术语确定后写入根 `GLOSSARY.md`；影响后续实现的架构决策记录在 `docs/adr/`。没有这些文件时按现有代码探索，等实际形成决策再建文档。
5. 安装依赖启用提交检查；在初始化 Git 后安装或运行 `pnpm setup:local`。按需执行静态检查并记录结果，自动化测试与浏览器验收仍遵循根 AGENTS 的用户授权约定。

初始化完成的标准：品牌与商品指向新产品，文档路径和命令可解析，功能开关与实际服务一致，检查入口及 CI 随仓库继承。不要从另一个产品整体覆盖模板的 AGENTS。

## 规则放置

| 内容                               | 位置                                       | 判断方式                               |
| ---------------------------------- | ------------------------------------------ | -------------------------------------- |
| 执行边界、按任务读取的入口         | `AGENTS.md`                                | 每次任务都需要，或决定何时读取其他文件 |
| 需要上下文判断的评审标准           | `CODING_STANDARDS.md`                      | 无法仅靠固定语法判断正确性             |
| 视觉与组件、主题、样式边界         | `DESIGN.md`                                | 页面实现需要立即查阅                   |
| 命名、导入、文件位置等机械约束     | Oxlint 或 `scripts/check-architecture.mjs` | 可以稳定地产生通过或失败结果           |
| 配置、部署、供应商用法             | 对应现有领域文档或技能                     | 只在相关任务需要                       |
| 商品权益、试用额度、模型、媒体限制 | 新项目自己的领域文档                       | 随产品变化，不属于模板默认值           |

同一规则保留一个权威位置，其他文件使用带触发条件的指针。机械规则接入已有 `pnpm check`，沿用 pre-commit 与 CI；不要只写一句“必须遵守”。

## 从产品回流

1. 记录具体失败及证据，区分实现选择、规则缺失、失效指针和已有检查未接线。先读模板现有规范与检查，避免重复建设。
2. 去掉产品名、绝对路径、供应商专用 ID、业务额度和一次性设计选择。可复用的是决策方法和边界，不能假设另一个项目的依赖、组件 API、Provider、命令或部署能力存在。
3. 以模板真实代码核对路径、导出和 API；保留已有单一事实源。模板没有的基础能力若确实要引入，作为明确实现改动处理，不在规则中先声称存在。
4. 机械约束进入检查器；样式文件例外在 `scripts/style-policy.json` 中使用精确路径与用途，不使用整目录通配来绕开边界。用途是否合理由评审判断。
5. 评审对照原失败确认修改覆盖原因；报告检查结果与剩余边界。既有项目单独挑选模板 diff，保留自己的品牌与业务规则，不直接覆盖。

- Filmcraft：Tailwind 优先、语义颜色、幂等副作用、规则进入现有检查可复用；编辑器旧类、试用额度、渲染链路和专用发布命令不进入模板。
- 模板 main 已有 pre-commit、CI、共享 UI 与国际化检查，本次在这些入口上补齐样式边界，不重复搭建护栏。
