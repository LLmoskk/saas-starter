## 模板为什么容易继续产生偏差

原 AGENTS.md 只有技术栈、技能入口和模板初始化提醒，缺少行为保留、付费调用、产物归属和交付范围。ponytail 的“最小 diff”约束代码量，不能保证示例、默认值和跳转语义不变。

技能入口也缺少取舍规则。供应商技能说明如何接入，不决定本项目是否要新增独立支付入口。会话 2 最终因用户希望并入既有 Waffo 收银台而撤销支付宝接入，说明集成前检查现有流程更有价值。

两个项目已经积累了可用规则，但不能整段复制：musitools 规定上线前同步生产 schema，FilmCraft 则明确不自动执行该命令；模板当前还是手动 CLI 发布，push 不会自动部署。翻译流程与 UI 包路径也不同。模板应继承判断原则与查阅触发条件，具体执行路径由新项目自己维护。

## 自动检查候选

模板已有 `pnpm check`，实际执行 `oxlint && oxfmt --check`；另有 `pnpm check-types`。当前 `.oxlintrc.json` 的 rules 为空，未看到 type、文件命名、浏览器 import 边界等显式规则；根目录未发现 `.husky` 或 `.github`，没有看到 pre-commit 或 CI 将检查接入交付流程。这是现有检查未接入护栏的缺口，不能声称模板已具有另外两个项目的保护能力。

建议后续单独实施，优先复用现有 oxlint：

1. 将现有 lint 与类型检查接入 pre-commit 或 CI。测试继续遵守用户显式要求才运行的约定。
2. 为 type 优先、文件命名和浏览器服务端 import 边界配置确定性检查，按框架生成文件与服务端目录设置必要例外。
3. 新项目引入真实付费服务后，给默认构建、发布入口设置防付费验收检查；资源规格与释放约束依据该项目资源合同检查，不复制 FilmCraft 的具体内存数值。

本次只调整规则文档，未新增 hook、CI、lint 规则或测试，也未调用任何付费业务服务。
